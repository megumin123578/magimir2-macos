# Controlled runtime checklist

Run this only on a macOS ARM64 test machine with a dedicated test account and
non-sensitive sample images.

## Integrity before launch

```bash
codesign --verify --deep --strict --verbose=4 MagiMir2.app
spctl -a -vv --type execute MagiMir2.app
stapler validate MagiMir2.app
```

Record the output together with the DMG SHA-256 already documented in
`MagiMir2_analysis_report.md`.

## UI capture sequence

1. Cold launch and updater gate.
2. Login choices, agreement, verification-code flow, store selection and device
   limit dialog. Use a test account; do not submit real personal credentials.
3. Empty home/project state and photo import.
4. Each editing tab with a neutral sample image.
5. Preset create/update/import/share dialogs.
6. Camera discovery only if a dedicated test camera is available.
7. Local export, export queue, pause/resume/cancel and history.
8. Feedback and purchase dialogs without completing a transaction.

For each state, record the triggering action, screenshot, visible fields,
enabled/disabled controls, and resulting local file changes.

## Network contract capture

Capture only traffic generated by the controlled test flow. For every request,
record:

- method and path;
- request content type and field names with tokens/PII redacted;
- response status and schema with identifiers redacted;
- whether an image or diagnostic archive leaves the machine;
- retry, timeout and cancellation behavior;
- whether the request uses the inferred v2 envelope.

Do not replay state-changing requests, bypass certificate validation, or probe
routes outside the actions performed by the test user.

## Native channel capture

Record method-channel names, method names, argument keys, return shapes, progress
events, error codes and cancellation behavior for import, preview, processing,
camera and export. Use this evidence to define adapter interfaces before writing
native implementations.
